## 说明与已知口径

- b0 跨库候选按余弦相似度直接排序（同一 embedding 模型同一向量空间）；b0/b1/b2 共享同一次混合检索调用的时延，代表整管线开销，单独部署某一路时延更低。
- b4（CRAG）以 top_k=max(K) 调用以支持 K 档评测；分级 prompt 会看到全部候选，与生产默认 top_k=6 存在轻微口径差异。
- b3 未配置 rerank 模型时自动跳过；b4 未配置默认 LLM 时自动跳过。
- 性能观察：混合检索对每个库各发起一次查询向量 embedding 调用（本次 10 库即约 10 次/题），各库共用同一 embedding 模型时可合并为单次调用以显著降低时延，属后续优化项。
- 逐题命中明细与 badcase 见同目录 per_question_*.jsonl（retrieved 字段为各配置 top10 键序）。
- 负例仅用于二期 QA/拒答评测，不参与本报告指标。

## 基线解读与 badcase 分析

**核心发现**

1. **向量路单独使用（b0）排序质量高于生产混合链路（b2）**：NDCG@6 0.957 vs 0.901，召回持平（0.98）。当前小语料 + 强 embedding 场景下，RRF 融合引入的 BM25 候选在部分题目上稀释了向量排序（典型：q041，向量路能排进 top6 的「离职归还资产」切片被融合挤出前 6）。可尝试的优化：加权 RRF（调低 BM25 路）、扩大融合候选深度后交由 rerank 纠序。
2. **BM25 的独有价值真实存在但有限**：q042（入职当天手续）向量 top6 缺「账号生命周期」切片，BM25 靠「入职当天」关键词锚点命中并保留在融合结果中——50 题中 b1 独有贡献 1 题、b0 独有贡献 1 题（q041，但被融合丢弃）。两路互补成立，融合的净收益依赖精排兜底。
3. **CRAG（b4）在当前语料上弊大于利**：Recall@6 由 0.98 降至 0.96，p95 时延 5.9s → 13.7s，LLM 调用 +1.12 次/题。根因（q017）：基线召回已接近饱和时，「不足」分级后的查询改写会漂移——原查询已命中的 gold 被改写查询的全新结果**替换**而非合并。修复方向：改写轮结果与上一轮做并集（按分数归并）而非直接替换；或提高分级门槛。
4. **标注噪音**：q046 的 grade-1 gold（安全事件分级）语义边缘，两路均未进 top6，属标注偏宽而非检索缺陷，解读时剔除。
5. **性能瓶颈明确**：每题约 19 次 embedding API 调用（混合检索逐库 10 次 + CRAG 重检轮），p50 5.6s 几乎全部为串行 API 往返。各库共用同一 embedding 模型时，查询向量应合并为单次调用（预计时延降一个数量级），属低成本高收益优化。

**badcase 清单（b2 视角）**

- q017 招待费审批：口语「请客户吃饭」vs 术语「业务招待」，gold 排第 5（NDCG@6 0.387），CRAG 改写后彻底丢失——同义改写鸿沟 + 改写策略缺陷的复合案例，也是引入 rerank 的典型受益场景。
- q041 离职资产：资产归还信息内嵌于「损坏与赔偿」切片，切片语义主体偏赔偿导致排位靠后——切分主题混杂问题的实例。
- q046 钓鱼演练：见标注噪音。

**参考达标线对照（b2）**：Recall@6 0.98（目标 0.90 ✓）、NDCG@6 0.901（目标 0.85 ✓）、MRR@6 0.898（目标 0.80 ✓）——三项全部达成；但 b0 的对比说明融合排序仍有明确优化空间。
