## 说明与已知口径

- b0 跨库候选按余弦相似度直接排序（同一 embedding 模型同一向量空间）；b0/b1/b2 共享同一次混合检索调用的时延，代表整管线开销，单独部署某一路时延更低。
- b4（CRAG）以 top_k=max(K) 调用以支持 K 档评测；分级 prompt 会看到全部候选，与生产默认 top_k=6 存在轻微口径差异。
- b3 未配置 rerank 模型时自动跳过；b4 未配置默认 LLM 时自动跳过。
- 性能口径：查询向量按（embedding 模型, 维度）分组嵌入，同组一次调用；本语料存在两种记录的模型名（KB6/8 为 text-embedding-v3、其余为 embedding-3）各成一组，即约 2 次/题。
- 逐题命中明细与 badcase 见同目录 per_question_*.jsonl（retrieved 字段为各配置 top10 键序）。
- 负例仅用于二期 QA/拒答评测，不参与本报告指标。

## v2 解读：三项改动验证与 rerank 增益量化（对照 baseline）

1. **任务③ embedding 分组生效**：查询向量嵌入 10 次/题 → 2 次/题，混合检索 p50 5595ms → 1426ms（-74%），全量评测 660s → 216s。KB6/8 记录旧模型名 text-embedding-v3 与其余库的 embedding-3 各成一组；两组解析到的实际配置不同，保持分组语义正确。统一旧库模型名元数据（需先核实其向量实际构建模型）可再收敛为 1 次/题。
2. **任务② CRAG 并集修复生效**：b4 Recall@6 0.96 → 0.99（超过 b2 的 0.98）；q017 NDCG@6 0.387 → **1.000**（并集把上一轮 rank-5 的 gold 与改写轮命中融合至榜首），q041 0.50/0.760 → 1.00/1.00。改写漂移造成的召回损失已消除；p50 2500ms 为 CRAG 分级 LLM 调用的固有代价。
3. **任务① b3 量化结论：该 rerank（智谱免费 rerank，阈值 0.2）为净负增益**：
   - NDCG@6 0.9008（融合序）→ 0.8231，MRR@6 0.898 → 0.785；
   - 掉分最多：q031 -0.567、q020 -0.500、q006 -0.500、q032 -0.392、q034 -0.380——典型失败为跨域近似文本混淆（「客户工单分级」候选被「IT 工单分级」压过）；
   - 局部正贡献：q017 +0.244、q041 +0.240；Recall@3 0.88 → 0.953（头部召回改善），说明阈值过滤有效但该模型排序能力不足；
   - **处置**：rerank 配置保留于模型配置页（默认已关闭，生产回到融合序）；若后续接入更强 rerank 模型，先跑 `--configs b3` 验证净增益再设默认。
4. **推荐生产配置 = 融合序 + CRAG 并集（无 rerank）**：v3-final 跑批确认中，见 report_v3-final_*.md。
